Uso: pgddl [-h] [--version] COMANDO ...

PG DDL Runner 0.5.1 — executor sequencial de DDL PostgreSQL.

Opções:
  -h, --help      Mostra esta ajuda e sai.
  --version       Mostra a versão e sai.

Comandos disponíveis:
  COMANDO
    plan          Analisa o arquivo DDL sem conexão ao banco.
    dry-run       Analisa locks, estrutura e dependências no banco (somente
                  leitura).
    status        Consulta o progresso, checkpoints e erros pendentes ou
                  resolvidos.
    apply         Aplica ou retoma o DDL na ordem original, com checkpoint por
                  comando.
    ack           Reconhece manualmente o próximo passo pendente, sem executar
                  seu SQL.
    dependencies  Identifica views dependentes de um ALTER COLUMN TYPE e
                  exporta backup.
    report        Gera relatório HTML de execução, tempos, erros e histórico.
    validate      Confere propriedades estruturais simples dos passos
                  confirmados.

Fluxo recomendado (teste em clone):
  ./pgddl plan atualizacao.ddl
  ./pgddl dry-run atualizacao.ddl -d erp -U postgres -p 15777
  ./pgddl apply atualizacao.ddl -d erp -U postgres -p 15777 --max-steps 20
  ./pgddl status atualizacao.ddl -d erp -U postgres -p 15777
  ./pgddl report atualizacao.ddl -d erp -U postgres -p 15777 --validate

Para ver opções, valores padrão e exemplos de um comando:
  ./pgddl apply -h
  ./pgddl <comando> -h

Windows: use .\pgddl.cmd no lugar de ./pgddl; conexão via TCP
normalmente exige -H HOST e credenciais libpq/pgpass.conf.

Códigos de saída:
  0   Sucesso ou pausa programada; consulte status.
  1   Falha de preparação, controle ou conexão (fora do DDL).
  2   Erro de argumentos (CLI) ou falha durante DDL/checkpoint.
  3   Pausa após WARNING; passo já confirmado.
  4   Alertas no dry-run, materialized view em dependencies ou divergência na validação.
  130 Interrupção por Ctrl+C; consulte status antes de retomar.

Segurança: apply modifica o banco; ack modifica o histórico. Não há rollback
global. Use o mesmo arquivo original na retomada e preserve o histórico.

                  [--full]
                  ARQUIVO.ddl

Analisa o arquivo DDL sem conexão ao banco.

========== dry-run ==========

Uso: pgddl dry-run [-h] [--encoding {auto,utf-8,utf-8-sig,cp1252,latin-1}]
                     -d BANCO [-H HOST] [-p PORTA] [-U USUARIO]
                     [--schema SCHEMA] [--migration-id ID]
                     [--lock-timeout SEG] [--statement-timeout SEG]
                     [--log ARQUIVO] [--verbose] [--locks-only]
                     [--max-steps N]
                     ARQUIVO.ddl

Analisa locks, estrutura e dependências no banco (somente leitura).

Argumentos posicionais:
  ARQUIVO.ddl           Arquivo DDL original da desenvolvedora.

Opções:
  -h, --help            Mostra esta ajuda e sai.
  --encoding {auto,utf-8,utf-8-sig,cp1252,latin-1}
                        Codificação do arquivo (padrão: auto).

Conexão e identidade da migração:
  -d, --dbname BANCO    Nome literal do banco, obrigatório (não URI/conninfo).
  -H, --host HOST       Host ou diretório do socket; quando omitido, usa
                        padrão libpq/PGHOST.
  -p, --port PORTA      Porta PostgreSQL; quando omitida, usa padrão
                        libpq/PGPORT.
  -U, --user USUARIO    Papel PostgreSQL; quando omitido, usa padrão
                        libpq/PGUSER.
  --schema SCHEMA       Schema alvo e search_path (padrão: public).
  --migration-id ID     ID estável da atualização (padrão: nome do arquivo).
                        Preserve na retomada.

Timeouts e log:
  --lock-timeout SEG    Limite por aquisição de lock (padrão: 3 s); 0 sem
                        limite, não recomendado.
  --statement-timeout SEG
                        Limite por instrução (padrão: 0, sem limite).
  --log ARQUIVO         Log local (Windows: %LOCALAPPDATA%\PGDDL\logs; Linux:
                        ~/.local/state/pgddl/logs; PGDDL_STATE_HOME
                        personaliza).

Opções de dry-run:
  --verbose             Mostra todos os passos analisados, não somente
                        alertas/resumo.
  --locks-only          Analisa locks sem a análise estrutural e de
                        dependências adicional.
  --max-steps N         Limita passos pendentes analisados (padrão: 0, todos).

Não aplica DDL nem cria histórico. Os locks observados podem mudar.
Exemplo: ./pgddl dry-run atualizacao.ddl -d erp -U postgres -p 15777 --verbose

========== apply ==========

Uso: pgddl apply [-h] [--encoding {auto,utf-8,utf-8-sig,cp1252,latin-1}]
                   -d BANCO [-H HOST] [-p PORTA] [-U USUARIO]
                   [--schema SCHEMA] [--migration-id ID] [--lock-timeout SEG]
                   [--statement-timeout SEG] [--log ARQUIVO]
                   [--backup-dir DIRETORIO]
                   [--dependency-policy {stop,rebuild-views}]
                   [--lock-policy {nowait,wait,retry}] [--retry-interval SEG]
                   [--retry-timeout SEG] [--monitor-interval SEG] [--yes]
                   [--verbose] [--max-steps N] [--continue-on-warning]
                   [--parallel-maintenance-workers N]
                   [--maintenance-work-mem MEMORIA]
                   ARQUIVO.ddl

Aplica ou retoma o DDL na ordem original, com checkpoint por comando.

Argumentos posicionais:
  ARQUIVO.ddl           Arquivo DDL original da desenvolvedora.

Opções:
  -h, --help            Mostra esta ajuda e sai.
  --encoding {auto,utf-8,utf-8-sig,cp1252,latin-1}
                        Codificação do arquivo (padrão: auto).

Conexão e identidade da migração:
  -d, --dbname BANCO    Nome literal do banco, obrigatório (não URI/conninfo).
  -H, --host HOST       Host ou diretório do socket; quando omitido, usa
                        padrão libpq/PGHOST.
  -p, --port PORTA      Porta PostgreSQL; quando omitida, usa padrão
                        libpq/PGPORT.
  -U, --user USUARIO    Papel PostgreSQL; quando omitido, usa padrão
                        libpq/PGUSER.
  --schema SCHEMA       Schema alvo e search_path (padrão: public).
  --migration-id ID     ID estável da atualização (padrão: nome do arquivo).
                        Preserve na retomada.

Timeouts e log:
  --lock-timeout SEG    Limite por aquisição de lock (padrão: 3 s); 0 sem
                        limite, não recomendado.
  --statement-timeout SEG
                        Limite por instrução (padrão: 0, sem limite).
  --log ARQUIVO         Log local (Windows: %LOCALAPPDATA%\PGDDL\logs; Linux:
                        ~/.local/state/pgddl/logs; PGDDL_STATE_HOME
                        personaliza).

Opções de apply:
  --backup-dir DIRETORIO
                        Histórico das views (Windows:
                        LOCALAPPDATA/PGDDL/views; Linux:
                        ~/.local/state/pgddl/views).
  --dependency-policy {stop,rebuild-views}
                        stop: exporta e pausa (padrão); rebuild-views:
                        reconstrói apenas views comuns suportadas, em
                        transação.
  --lock-policy {nowait,wait,retry}
                        nowait: pré-lock imediato (padrão); wait: fila com
                        timeout; retry: repete pré-lock sem permanecer na
                        fila.
  --retry-interval SEG  Intervalo entre tentativas do pré-lock (padrão: 5 s,
                        só retry).
  --retry-timeout SEG   Janela de novas tentativas por passo (padrão: 300 s,
                        só retry).
  --monitor-interval SEG
                        Intervalo do monitor de locks/índices (padrão: 2 s); 0
                        desativa.
  --yes                 Dispensa confirmação do nome do banco, inclusive em
                        automação. Não ignora erros.
  --verbose             Exibe SQL integral de cada passo durante a execução.
  --max-steps N         Pausa após N novos comandos confirmados (padrão: 0,
                        sem limite).
  --continue-on-warning
                        Continua após WARNING; por padrão pausa após confirmar
                        o passo. Não ignora erros SQL.
  --parallel-maintenance-workers, --max-parallel-maintenance-workers N
                        Limite de workers nativos de manutenção nesta sessão;
                        0 desativa. Omitir preserva configuração.
  --maintenance-work-mem MEMORIA
                        Memória de manutenção da sessão, ex.: 512MB. Unidades
                        kB, MB ou GB. Omitir preserva configuração.

ALTERA O BANCO. Revise o SQL, faça backup e teste em clone.
Retome com o mesmo arquivo, schema, papel e ID; não edite o arquivo.
Exemplos:
  ./pgddl apply atualizacao.ddl -d erp -U postgres -p 15777 --max-steps 20
  ./pgddl apply atualizacao.ddl -d erp -U postgres -p 15777 --lock-policy retry
  ./pgddl apply atualizacao.ddl -d erp -U postgres -p 15777 --dependency-policy rebuild-views
Materialized views bloqueiam a reconstrução automática, mesmo quando autorizada.

  --schema SCHEMA       Schema alvo e search_path (padrão: public).
  --migration-id ID     ID estável da atualização (padrão: nome do arquivo).
                        Preserve na retomada.

Timeouts e log:
